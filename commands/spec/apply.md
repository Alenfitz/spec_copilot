请按 /apply 流程执行：

**变更名**：$ARGUMENTS

## 前置检查

1. `npx @alenfitz/spec-copilot gate <变更名> apply`
2. Gate 通过 → `git checkout -b feature/<变更名>`（如已在分支则跳过）
3. 告知用户当前分支

## 阶段锁

- `/spec:apply` 只能在 `spec.md + tasks.md + log.md` 已存在且 apply gate 通过后进入。
- 如果用户没有先走 `/spec:propose`，不得自行脑补 spec 后直接编码。
- 用户即使说"全部执行"、"不要停顿"，也必须遵守本命令的逐 task 停顿；唯一例外只有用户**显式**使用 `/spec:flow`。

## 逐 task 执行（铁律：一个 task 一停）

> 🛑 **完成一个 task 后必须完全停止，等用户说"继续"才执行下一个。**
> 禁止连续执行多个 task。即使用户说"全部执行"，仍必须逐 task 停顿。

每个 task 流程：
1. 编码实现
2. 验证（编译/构建/运行）
3. 展示验证证据（见下方要求）
4. `git commit`
5. 更新 tasks.md 该 task 状态为 ✅
6. **🛑 停止，输出：**
   ```
   ✅ T<n> 完成（<简述>）
   验证：<编译/测试结果>
   功能：<curl 输出 / 页面行为>
   文件：<实际改动文件列表>
   Commit: <hash>

   → 下一步：T<n+1>: <描述>
   → 说"继续"执行下一个
   ```
7. **等用户回复**

### 验证证据要求

> 编译通过 ≠ 功能完成。

- **后端 task**：必须执行 tasks.md 定义的 curl 验证，展示实际返回。返回异常 ≠ ✅
- **前端 task**：必须说明页面可访问路径、核心交互是否真的可操作。按钮 handler 是空 TODO ≠ ✅
- **文件清单**：对比计划 vs 实际，遗漏的必须说明原因

### 反"AI 编造"必填字段（每个 task 标 ✅ 前都填）

任一留空，gate review 会阻断：

1. **实际验证结果**：原始未加工命令输出，以 `$ ` / `>>> ` / `HTTP/` 起始。禁止"通过"、"返回正常"。
2. **实际文件清单**：列出实际修改的文件，与计划对比。
3. **未实现声明**（三项必填，无则写"无"）：
   - 未完成的功能点
   - 已知缺陷或 TODO
   - 简化或降级处理
4. **自评**：用户拿这代码能干什么、扣分理由、自评分（0-100）

### Scope 偏差处理

- 发现某计划文件无法实现或需跳过 → **立即告知用户等确认**，不得静默裁切
- 偏差当场记录到 log.md `Spec-Code 偏差记录`

## 全部 task 完成后

1. 填写 tasks.md "变更摘要"
2. 输出：
   ```
   /spec:apply 完成 ✓
   总 Task：<N>，总 Commit：<N>
   → 下一步：/spec:smoke <变更名>
   ```
3. **停止，等用户触发 smoke。**

核心原则：**AI 负责执行，用户负责推进节奏。**
